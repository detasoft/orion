## PULL: первый пользователь и проверка спроса

**Один конкретный сценарий для пилота (гипотеза):** технический руководитель небольшой
команды подрядчика должен выдать двум разработчикам и одному наблюдателю доступ
к новому репозиторию на управляемом командой сервере до начала клиентского проекта.
Администратор ставит артефакт, создаёт доступы; разработчик клонирует и отправляет
коммит; наблюдатель читает, но не может отправить изменения; после restart всё
сохраняется. Число участников — дизайн проверочного сценария, не найденный клиент.

| PULL | Ответ | Статус доказательства |
| --- | --- | --- |
| Project | Запустить приватный Git remote с разграничением чтения/записи и понятной эксплуатацией | Технически проверяемый сценарий; реальный заказчик не назван |
| Unavoidable | Возможный триггер — конкретная дата старта проекта и требование разместить код на своей инфраструктуре | Ни дата, ни требование клиента не подтверждены; релизный план автора не создаёт срочности у покупателя |
| List of options | Существующий Git-сервис, bare Git + SSH, Gitea, Forgejo, GitLab Self-Managed, оставить текущую схему | Реальные альтернативы; неизвестно, какие уже пробовал предполагаемый клиент |
| Limitations | Для bare Git может потребоваться собственная процедура управления правами; для GitLab нужно оценить стоимость эксплуатации; для Gitea/Forgejo доказанного ограничения нет | Только гипотезы для интервью; оснований объявить Orion лучшим нет |

Gitea и Forgejo уже документируют установку из бинарного файла, поэтому само обещание
«легко поставить свой Git-сервер» не является доказанным отличием Orion.
Источники: [Gitea](https://docs.gitea.com/installation/install-from-binary/),
[Forgejo](https://forgejo.org/docs/latest/admin/installation/binary/), проверено 29 октября.
GitLab документирует требования к CPU, памяти и компонентам; это повод измерить
операционные затраты для конкретной команды, а не объявлять его непригодным.
[GitLab requirements](https://docs.gitlab.com/install/requirements/).

**Почему пробовать Orion сейчас?** Для внешнего клиента убедительный ответ пока не
доказан. Разумный пилот — проверка существующей программируемой конфигурации/ACL и
операционного сопровождения на некритичном репозитории при доступности автора.
Это предложение эксперимента, не подтверждённая причина миграции и не готовность платить.

**Связь с обсуждением «Поиск ниши Orion».** Там shared workspace для нескольких AI-агентов
предложен как гипотеза будущей ценности и прямо не заявлен реализованным. Это другой
Project: сократить повторную интеграцию изменений и работу на устаревшем контексте.
Его Unavoidable также не доказан; варианты — worktrees, ветки, последовательная работа,
обычный review/merge. Приписывать эти преимущества нынешнему Git-hosting preview нельзя.
В текущий scope агентные функции не добавляются.

**Как закрыть неопределённость без нового кода:** найти одного добровольного оператора,
попросить описать последний реальный запуск/миграцию Git-сервера, дедлайн, последствия
бездействия, уже испробованные варианты и их конкретные ограничения. Затем дать
ему исправленный артефакт и измерить время установки, число подсказок автора,
результат SSH/ACL/restart/restore. Критерий пилота: весь сценарий воспроизводим по
инструкции, нет необъяснённой потери данных/обхода ACL, оператор сам хочет продолжить
использование ради названной задачи. Платный спрос требует отдельного согласия
покупателя, а не количества функций или скачиваний.

Открыты: личность первого пользователя; реальный дедлайн/стоимость проблемы;
ограничение уже опробованной альтернативы; согласие на пилот и оплата;
владелец поддержки/канал обращения. Эти факты невозможно достоверно вывести из кода.
Внешние интервью, приглашения и сообщения не отправлялись.

## Передача результатов

Все результаты относятся к зафиксированному SHA выше. Параллельные сессии изменяли
основной checkout, в том числе появились изменения упаковки и `DistributionArchiveIT`;
они не принадлежат этому запросу и не входят в отчётный коммит. Проверка их исправлений
не заявляется. Для текущей работы production-код не менялся, новые архитектурные
концепции не вводились. Документы проверены на соответствие фактическим результатам;
неуспешный тестовый gate не скрыт диагностической сборкой с `-DskipTests`.
