# Module review: net/git-transport

## 6. Lifecycle tests закрепляют случайную форму наследования и DI constructor

- **Проблема и триггер.** [Native test](src/test/java/pro/deta/orion/transport/git/GitNativeTransportStateMachineTest.java#L163) требует конкретный superclass, на строке 170 — один параметр Inject constructor. [SSH test](src/test/java/pro/deta/orion/transport/git/GitSshTransportStateMachineTest.java#L85) также фиксирует superclass. Внутренняя перестройка ломает их независимо от lifecycle поведения.
- **Источники и владельцы.** [Native adapter](src/main/java/pro/deta/orion/transport/git/GitNativeTransportStateMachine.java#L13), [SSH adapter](src/main/java/pro/deta/orion/transport/git/GitSshTransportStateMachine.java#L13), helper native test на строке 381. Реальный [aggregate](../transport/src/main/java/pro/deta/orion/transport/TransportLifecycleStateMachine.java#L38) использует raw stateMachine обоих adapters. Содержательное coverage: native start/stop и start failure того же теста, SSH bind failure и host-key authentication того же SSH теста.
- **Документированное поведение.** Class AiRule требует публичный raw StateMachine API. [План](../../docs/plans/tasks/11_git/05_virtual-thread-server-transport.md) сохраняет adapters для startup/shutdown; точный superclass и число dependencies не требуются.
- **Контракт.** Сохранить lifecycle, singleton DI wiring, состояния/ошибки и raw stateMachine composition. Java inheritance shape и число constructor parameters — детали реализации.
- **Минимальное исправление.** Удалить два inheritance-only теста и constructor count assertion с ненужным helper/imports. Сохранить Singleton framework assertion, поведенческое lifecycle/auth/socket coverage и production API.
- **Альтернативы и последствия.** Проверка точной формы блокирует корректные refactors. Blanket reflection deletion снимет реальные credential setup и framework проверки; production менять не требуется.
- **Уверенность.** Высокая по тестам и consumers. Production failure не заявляется; runtime tests не запускались.
- **Важность / простота.** Низкая важность: хрупкие тесты. Высокая простота: автоматическое удаление incidental assertions при существующем behavioral coverage.

## 7. Ошибка bind оставляет неопубликованный listener без deterministic close

- **Проблема и триггер.** При занятом TCP port onStart создаёт ServerSocket, затем bind бросает IOException до publication в serverSocket. Catch не закрывает локальный listener; последующий onStop видит null. Descriptor остаётся до JDK Cleaner; постоянная утечка не утверждается.
- **Источники и владельцы.** [Создание/bind/catch](src/main/java/pro/deta/orion/transport/git/GitNativeTransportService.java#L54), [stop](src/main/java/pro/deta/orion/transport/git/GitNativeTransportService.java#L78), production [leaf lifecycle](../../core/common-runtime/src/main/java/pro/deta/orion/lifecycle/state/ServiceLifecycleStateMachineAdapter.java#L70) и [aggregate](../transport/src/main/java/pro/deta/orion/transport/TransportLifecycleStateMachine.java#L44). [Socket tests](src/test/java/pro/deta/orion/transport/git/GitNativeTransportStateMachineTest.java#L65) проверяют успешный bind/stop, failure-to-ERR test на строке 207 использует fake service и не проверяет failed bind ownership. Owner — GitNativeTransportService.
- **Документированное поведение.** Leaf lifecycle допускает ERR→STOP для cleanup. [План](../../docs/plans/tasks/11_git/05_virtual-thread-server-transport.md) сохраняет ответственность adapters за startup/shutdown; требования полагаться на GC не найдено.
- **Контракт.** Service владеет созданным socket до успешной передачи field/accept loop. Сохранить original bind failure, isRunning/boundPort и успешный listener lifecycle.
- **Минимальное исправление.** Закрывать локальный listener при неуспехе до publication существующим closeListener; сохранять исходную ошибку. Проверить occupied-port startup failure, последующий stop и recovery, включая meaningful resource cleanup observation.
- **Альтернативы и последствия.** Publication до bind открывает промежуточное unbound состояние. Ожидание Cleaner оставляет длительность удержания неопределённой. Constructor-with-bind может закрывать при ошибке, но требует проверки address/backlog equivalence; локальный cleanup меньше, новый registry/factory API не нужен.
- **Уверенность.** Высокая по коду и установленному Corretto21 src.zip: ServerSocket.bind и NioSocketImpl.bind не закрывают созданный fd при bind exception, create регистрирует Cleaner. Custom runtime/providers и actual FD count не проверялись.
- **Важность / простота.** Средняя важность: обычный port conflict удерживает resource до GC, повторные failures могут накопить descriptors; масштаб не измерен. Локальная поправка ownership через Simple.
