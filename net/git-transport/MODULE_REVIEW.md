# Module review: net/git-transport

## 7. Ошибка bind оставляет неопубликованный listener без deterministic close

- **Проблема и триггер.** При занятом TCP port onStart создаёт ServerSocket, затем bind бросает IOException до publication в serverSocket. Catch не закрывает локальный listener; последующий onStop видит null. Descriptor остаётся до JDK Cleaner; постоянная утечка не утверждается.
- **Источники и владельцы.** [Создание/bind/catch](src/main/java/pro/deta/orion/transport/git/GitNativeTransportService.java#L54), [stop](src/main/java/pro/deta/orion/transport/git/GitNativeTransportService.java#L78), production [leaf lifecycle](../../core/common-runtime/src/main/java/pro/deta/orion/lifecycle/state/ServiceLifecycleStateMachineAdapter.java#L70) и [aggregate](../transport/src/main/java/pro/deta/orion/transport/TransportLifecycleStateMachine.java#L44). [Socket tests](src/test/java/pro/deta/orion/transport/git/GitNativeTransportStateMachineTest.java#L63) проверяют успешный bind/stop, [failure-to-ERR test](src/test/java/pro/deta/orion/transport/git/GitNativeTransportStateMachineTest.java#L199) использует fake service и не проверяет failed bind ownership. Owner — GitNativeTransportService.
- **Документированное поведение.** Leaf lifecycle допускает ERR→STOP для cleanup. [План](../../docs/plans/tasks/11_git/05_virtual-thread-server-transport.md) сохраняет ответственность adapters за startup/shutdown; требования полагаться на GC не найдено.
- **Контракт.** Service владеет созданным socket до успешной передачи field/accept loop. Сохранить original bind failure, isRunning/boundPort и успешный listener lifecycle.
- **Минимальное исправление.** Закрывать локальный listener при неуспехе до publication существующим closeListener; сохранять исходную ошибку. Проверить occupied-port startup failure, последующий stop и recovery, включая meaningful resource cleanup observation.
- **Альтернативы и последствия.** Publication до bind открывает промежуточное unbound состояние. Ожидание Cleaner оставляет длительность удержания неопределённой. Constructor-with-bind может закрывать при ошибке, но требует проверки address/backlog equivalence; локальный cleanup меньше, новый registry/factory API не нужен.
- **Уверенность.** Высокая по коду и установленному Corretto21 src.zip: ServerSocket.bind и NioSocketImpl.bind не закрывают созданный fd при bind exception, create регистрирует Cleaner. Custom runtime/providers и actual FD count не проверялись.
- **Важность / простота.** Средняя важность: обычный port conflict удерживает resource до GC, повторные failures могут накопить descriptors; масштаб не измерен. Локальная поправка ownership через Simple.
