# Module review: core/key-material

## 1. Ошибка сохранения ACME оставляет доступным изменённое состояние памяти

- **Проблема и триггер.** Первая выдача ACME создаёт account/domain keys, затем запись хранилища завершается ошибкой. Следующий запрос на том же владельце находит оба alias и возвращает ключи без повторного сохранения. Неудачное сохранение установленной цепочки также оставляет её доступной через savedCertificate().
- **Источники и владельцы.** [Генерация и saveRequired](src/main/java/pro/deta/orion/keymaterial/KeyMaterialService.java#L504), [изменение цепочки](src/main/java/pro/deta/orion/keymaterial/KeyMaterialService.java#L520), [runtime capability](src/main/java/pro/deta/orion/keymaterial/OrionKeyMaterial.java#L227). Реальный singleton [AcmeCertificateService](../../net/http-core/src/main/java/pro/deta/orion/transport/http/AcmeCertificateService.java#L55) допускает следующий запрос в finally и передаёт ключи внешнему issuer; [savedCertificate](../../net/http-core/src/main/java/pro/deta/orion/transport/http/AcmeCertificateService.java#L96) обслуживает [HTTP route](../../net/http-core/src/main/java/pro/deta/orion/transport/http/OrionAdminAcmeCertificateRoute.java#L45). [Тест durable reuse](src/test/java/pro/deta/orion/keymaterial/KeyMaterialCapabilitiesTest.java#L288) проверяет успешное сохранение и повторное открытие.
- **Документированное поведение.** [OrionKeyMaterial](src/main/java/pro/deta/orion/keymaterial/OrionKeyMaterial.java#L15) требует инвалидировать runtime-владельца после failed material save и открыть durable state заново. Configuration cipher уже использует [close при ошибке](src/main/java/pro/deta/orion/keymaterial/OrionKeyMaterial.java#L128), проверенный [failure-тестом](src/test/java/pro/deta/orion/keymaterial/OrionKeyMaterialTest.java#L274).
- **Контракт.** Обязательны сохранение новых ACME-ключей перед передачей issuer и запрет представлять несохранённую цепочку как durable material. Семантика повторного публичного низкоуровневого KeyMaterialService.save() — отдельный mutable API и требует самостоятельного решения при её изменении.
- **Минимальное исправление.** На существующей границе runtime ACME-записи инвалидировать владельца через close() при ошибке сохранения. Изменение, сохранение и инвалидирование должны оставаться под monitor владельца. Проверить failed acquire → повторное обращение отвергнуто; failed install → цепочка недоступна как сохранённая; повторное открытие восстанавливает durable generation. Новое dirty/cache-состояние не требуется.
- **Альтернативы и последствия.** Глобальная инвалидизация внутри публичного save() меняет низкоуровневых consumers. Rollback/reload сложнее и должен учитывать запись с потерянным ответом. Существующий close/reopen требует восстановления runtime-владельца, сохраняя запрет использования неопределённой генерации; [потерянный ответ](src/test/java/pro/deta/orion/keymaterial/OrionKeyMaterialTest.java#L353) уже покрыт для cipher.
- **Уверенность.** Высокая: путь прослежен до реального HTTP-потребителя. Runtime-воспроизведение не запускалось; область обработки ошибки требует согласования.
- **Важность / простота.** Важность высокая: внешняя выдача может использовать ключи, отсутствующие после перезапуска, а API — показать несохранённый сертификат. Простота средняя: механизм закрытия существует, необходимы проверки ошибки записи, повторного обращения и восстановления.

## 2. Reflection-проверки фиксируют структуру API вместо поведения

- **Проблема и триггер.** Эквивалентное изменение представления контекста или API ломает четыре структурные проверки без изменения криптографического поведения. Имя возвращаемого типа не доказывает отсутствие утечки ключевого материала.
- **Источники и владельцы.** [ConfigurationSecretContextTest](src/test/java/pro/deta/orion/keymaterial/ConfigurationSecretContextTest.java#L13), встроенные assertions [SigningCapability](src/test/java/pro/deta/orion/keymaterial/KeyMaterialCapabilitiesTest.java#L51), [ConfigurationCipherCapability](src/test/java/pro/deta/orion/keymaterial/KeyMaterialCapabilitiesTest.java#L560), [OrionKeyMaterial](src/test/java/pro/deta/orion/keymaterial/OrionKeyMaterialTest.java#L187). Реальное поведение: [AAD-сериализация](src/main/java/pro/deta/orion/keymaterial/ConfigurationSecretContext.java#L18), consumers [ConfigurationSecrets](../common/src/main/java/pro/deta/orion/config/ConfigurationSecrets.java#L108), [JWT](../acl/src/main/java/pro/deta/orion/acl/JwtAccessTokenService.java#L98), [bootstrap wiring](../bootstrap/src/main/java/pro/deta/orion/BootstrapContext.java#L289).
- **Документированное поведение.** [Правила качества тестов](../../.agents/skills/orion-minimal-implementation/SKILL.md) запрещают reflection для случайной структуры. [План CA](../../docs/plans/tasks/20_internal-certificate-authority.md#L12) сохраняет ограничение доступа к raw material; требования перечислять методы и record components через reflection не найдено.
- **Контракт.** Сохранить capability boundaries, подпись/верификацию, привязку ciphertext к контексту, сохранённые envelopes и lifecycle владельца. Точный состав record и перечисление методов через reflection относятся к форме реализации.
- **Минимальное исправление.** Удалить только exposesOnlyStableSecretIdentity, три встроенных reflection-assertion и освободившийся import. Полностью сохранить остальные части этих тестов.
- **Альтернативы и последствия.** Source/bytecode inspection сохранит проблему. Дополнительные дублирующие тесты не нужны: signing/tamper, seal/reload, AAD, TLS, persistence и close уже проверяются по поведению.
- **Уверенность.** Высокая: assertions и реальные consumers проверены, обязательного рефлексивного контракта не найдено. Тесты во время аудита не запускались.
- **Важность / простота.** Важность средняя: нарушение правил качества тестов и лишняя связанность. Простота высокая: четыре локальных удаления без изменения production API.
