# Module review: core/key-material

## 1. Ошибка сохранения ACME оставляет доступным изменённое состояние памяти

- **Проблема и триггер.** Первая выдача ACME создаёт account/domain keys, затем запись хранилища завершается ошибкой. Следующий запрос на том же владельце находит оба alias и возвращает ключи без повторного сохранения. Неудачное сохранение установленной цепочки также оставляет её доступной через savedCertificate().
- **Источники и владельцы.** [Генерация и saveRequired](src/main/java/pro/deta/orion/keymaterial/KeyMaterialService.java#L504), [изменение цепочки](src/main/java/pro/deta/orion/keymaterial/KeyMaterialService.java#L520), [runtime capability](src/main/java/pro/deta/orion/keymaterial/OrionKeyMaterial.java#L227). Реальный singleton [AcmeCertificateService](../../net/http-core/src/main/java/pro/deta/orion/transport/http/AcmeCertificateService.java#L55) допускает следующий запрос в finally и передаёт ключи внешнему issuer; [savedCertificate](../../net/http-core/src/main/java/pro/deta/orion/transport/http/AcmeCertificateService.java#L96) обслуживает [HTTP route](../../net/http-core/src/main/java/pro/deta/orion/transport/http/OrionAdminAcmeCertificateRoute.java#L45). [Тест durable reuse](src/test/java/pro/deta/orion/keymaterial/KeyMaterialCapabilitiesTest.java#L286) проверяет успешное сохранение и повторное открытие.
- **Документированное поведение.** [OrionKeyMaterial](src/main/java/pro/deta/orion/keymaterial/OrionKeyMaterial.java#L15) требует инвалидировать runtime-владельца после failed material save и открыть durable state заново. Configuration cipher уже использует [close при ошибке](src/main/java/pro/deta/orion/keymaterial/OrionKeyMaterial.java#L128), проверенный [failure-тестом](src/test/java/pro/deta/orion/keymaterial/OrionKeyMaterialTest.java#L272).
- **Контракт.** Обязательны сохранение новых ACME-ключей перед передачей issuer и запрет представлять несохранённую цепочку как durable material. Семантика повторного публичного низкоуровневого KeyMaterialService.save() — отдельный mutable API и требует самостоятельного решения при её изменении.
- **Минимальное исправление.** На существующей границе runtime ACME-записи инвалидировать владельца через close() при ошибке сохранения. Изменение, сохранение и инвалидирование должны оставаться под monitor владельца. Проверить failed acquire → повторное обращение отвергнуто; failed install → цепочка недоступна как сохранённая; повторное открытие восстанавливает durable generation. Новое dirty/cache-состояние не требуется.
- **Альтернативы и последствия.** Глобальная инвалидизация внутри публичного save() меняет низкоуровневых consumers. Rollback/reload сложнее и должен учитывать запись с потерянным ответом. Существующий close/reopen требует восстановления runtime-владельца, сохраняя запрет использования неопределённой генерации; [потерянный ответ](src/test/java/pro/deta/orion/keymaterial/OrionKeyMaterialTest.java#L351) уже покрыт для cipher.
- **Уверенность.** Высокая: путь прослежен до реального HTTP-потребителя. Runtime-воспроизведение не запускалось; область обработки ошибки требует согласования.
- **Важность / простота.** Важность высокая: внешняя выдача может использовать ключи, отсутствующие после перезапуска, а API — показать несохранённый сертификат. Простота средняя: механизм закрытия существует, необходимы проверки ошибки записи, повторного обращения и восстановления.
