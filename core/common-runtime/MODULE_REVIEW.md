# Module review: core/common-runtime

## 1. Lifecycle-тесты закрепляют внутреннюю структуру через reflection

- **Проблема и триггер.** Несколько тестов проверяют параметры типов, имена объявленных методов и полей, точный список record components, отсутствие старого класса и модификатор accessor. Изменение структуры при сохранении lifecycle/status-поведения ломает эти проверки; полезное поведение ими не проверяется.
- **Источники и владельцы.** [Структурные блоки](src/test/java/pro/deta/orion/lifecycle/state/StateMachineTest.java#L55), [модификатор accessor](src/test/java/pro/deta/orion/lifecycle/state/StateMachineTest.java#L184), [reflection-helper](src/test/java/pro/deta/orion/lifecycle/state/StateMachineTest.java#L1827). Владельцы: [StateMachine](src/main/java/pro/deta/orion/lifecycle/state/StateMachine.java#L1), [StateMachineStatus](src/main/java/pro/deta/orion/lifecycle/state/StateMachineStatus.java#L1), [AggregateStateMachine](src/main/java/pro/deta/orion/lifecycle/state/AggregateStateMachine.java#L1). Реальная композиция: [transport aggregate](../../net/transport/src/main/java/pro/deta/orion/transport/TransportLifecycleStateMachine.java#L25), [bootstrap](../bootstrap/src/main/java/pro/deta/orion/component/OrionRuntimeStateMachine.java#L90); содержательные сценарии находятся в том же StateMachineTest.
- **Документированное поведение.** [README](README.md) описывает transitions, статусы, дочерние машины, последовательное и параллельное выполнение. [Правила проверки](../../.agents/skills/orion-minimal-implementation/SKILL.md) требуют наблюдаемое поведение и запрещают assertions о случайной внутренней структуре.
- **Контракт.** Обязательны корректные переходы, наблюдаемые статусы, композиция, порядок и обработка ошибок. Точное расположение полей и методов, record layout и наличие удалённого класса относятся к форме реализации. Необходимо сохранять действующий публичный API реальных consumers.
- **Минимальное исправление.** Удалить семь структурных тестов и освободившийся reflection-helper/imports; сохранить поведенческие сценарии поиска машин между этими блоками. Сохранить проверки transitions/status/композиции/ошибок и компиляцию реальных consumers; production API и lifecycle сохраняются.
- **Альтернативы и последствия.** Новая reflection-whitelist оставит ту же хрупкость. Удаление всего тестового класса потеряет существенное поведенческое покрытие. Локальное удаление структурных блоков устраняет нарушение без дополнительной production-абстракции.
- **Уверенность.** Высокая: assertions и реальные callers проверены статически. Тесты во время аудита не запускались.
- **Важность / простота.** Важность средняя: нарушение принятого тестового контракта и препятствие корректным изменениям. Простота высокая: изменения ограничены тестовым файлом, без runtime-изменений.
