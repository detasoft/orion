# Module review: tests/git-engine-test-support

## 5. Interruption обрывает остановку принадлежащего helper процесса git daemon

- **Проблема и триггер.** После прерванной Git-команды runner сохраняет interrupt. GitDaemonServer.close посылает destroy, обнуляет daemon, затем interruptible wait выбрасывает IOException: force-stop и ожидание завершения пропускаются. Такой же путь возникает при interrupted awaitReady и stopFailedAttempt. Ещё работающий процесс теряет владельца, повторный close ничего не делает.
- **Источники и владельцы.** [Close](src/main/java/pro/deta/orion/git/workflow/GitDaemonServer.java#L92), [startup cleanup](src/main/java/pro/deta/orion/git/workflow/GitDaemonServer.java#L177), [wait](src/main/java/pro/deta/orion/git/workflow/GitDaemonServer.java#L205). Реальные callers: [matrix](../git-engine-interoperability-matrix/src/test/java/pro/deta/orion/git/workflow/matrix/GitMatrixDefinition.java#L19), [harness](src/main/java/pro/deta/orion/git/workflow/GitInteroperabilityHarness.java#L16). [Daemon tests](src/test/java/pro/deta/orion/git/workflow/GitDaemonServerTest.java#L18) проверяют serve/port collision, но не interruption; соседний [runner test](src/test/java/pro/deta/orion/git/workflow/GitCommandRunnerTest.java#L62) проверяет bounded cleanup.
- **Документированное поведение.** Отдельной daemon cancellation спецификации не найдено. Owner реализует bounded graceful/forced shutdown; harness закрывает его до удаления root. [Runner comment](src/main/java/pro/deta/orion/git/workflow/GitCommandRunner.java#L14) закрепляет сохранение interruption при завершении cleanup.
- **Контракт.** Прерывание сценария не должно пропускать остановку дочернего процесса. До удаления root требуется завершение либо ошибка bounded shutdown; interrupt flag должен сохраняться.
- **Минимальное исправление.** Использовать существующий подход [waitForTermination](src/main/java/pro/deta/orion/git/workflow/GitCommandRunner.java#L133) в close и failed-start: ждать до deadline несмотря на interruption, восстановить flag, при необходимости force-stop. Сохранить startup failure и добавить cleanup error suppressed. Проверить interrupted stop/start и задержанный graceful stop реальными subprocess scenarios.
- **Альтернативы и последствия.** Один destroy теряет гарантию завершения; новый process manager или timeout thread не требуется. Достаточно локального алгоритма существующего владельца.
- **Уверенность.** Высокая по control flow. Выживание настоящего git daemon зависит от момента выхода после destroy и не воспроизводилось; постоянная утечка не утверждается.
- **Важность / простота.** Средняя важность: cancellation нарушает изоляцию процесса и каталога. Умеренная простота; lifecycle исправление через Simple.
