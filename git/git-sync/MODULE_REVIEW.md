# Module review: git/git-sync

## 3. Tracking refs публикуются без полного графа объектов

- **Проблема и триггер.** Upstream рекламирует commit C и возвращает корректный pack с C без tree T. Gateway сохраняет pack и публикует tracking C; CREATE_LOCAL attachment также может опубликовать live C с недоступным содержимым.
- **Источники и владельцы.** [Persist/publication](src/main/java/pro/deta/orion/git/sync/SmartHttpGitRemoteGateway.java#L65), [publisher](src/main/java/pro/deta/orion/git/sync/SmartHttpGitRemoteGateway.java#L158), [attachment](src/main/java/pro/deta/orion/git/sync/GitAttachment.java#L32), [live publication](src/main/java/pro/deta/orion/git/sync/GitAttachment.java#L59), [storage target existence](../git-parser/src/main/java/pro/deta/orion/git/parser/v2/storage/GitStorageApi.java#L90), [pack completion](../git-native-storage/src/main/java/pro/deta/orion/git/nativestorage/pack/PackIngestionOutput.java#L56), [gateway tests](src/test/java/pro/deta/orion/git/sync/SmartHttpGitRemoteGatewayTest.java#L56).
- **Документированное поведение.** [Принятый план](../../docs/plans/tasks/07_external-git-repository-sync/01_primary-upstream.md#L94) требует объекты до fetched view; [проверка restart](../../docs/plans/tasks/07_external-git-repository-sync/01_primary-upstream.md#L207) включает reachability. [Bootstrap-fetcher](../git-native-proxy/src/main/java/pro/deta/orion/git/proxy/NativeBootstrapGitFetcher.java#L38) и его [negative test](../git-native-proxy/src/test/java/pro/deta/orion/git/proxy/NativeBootstrapGitFetcherTest.java#L125) уже защищают этот контракт.
- **Контракт.** Все head targets должны иметь полный граф в объединённом local storage до любого tracking publication. При incomplete root все tracking refs сохраняются; attachment не получает успешный snapshot.
- **Минимальное исправление.** После persist и до единственного atomic CAS проверить уникальные roots существующим NativeGitRepository.hasCompleteObjectClosure; при отказе вернуть доменную gateway ошибку. Проверить missing tree, несколько heads с одним incomplete, неизменность tracking/live refs и reuse законных local objects.
- **Альтернативы и последствия.** Target existence недостаточно; проверка только нового pack отвергнет законные local objects. Перенос обхода во все updateRefs расширяет стоимость/контракт. Unreferenced pack допустим; повреждённый graph публиковать нельзя.
- **Уверенность.** Высокая по цепочке и существующему аналогичному тесту; runtime repro не выполнялся. Sync orchestration ещё не подключена: finding относится к реализованному gateway/attachment API.
- **Важность / простота.** Важность высокая для integrity при incomplete upstream, поверхность ограничена foundation API. Простота средняя: существующий механизм и поведенческие сценарии.
